# LearnLoop v2.0 Release Notes

**Release Date:** 2026-09-04

---

## Major Changes

### Orchestrator State Machine (v2.0)

LearnLoop now enforces a strict state machine with **mandatory blocking guards** that prevent skipping critical stages:

**4 Guard Checkpoints:**
- **G1 (Pre-WAVE1):** Blocks agent spawns if interview incomplete
- **G2 (Post-WAVE1):** Verifies all 4 discovery agents completed
- **G3 (Post-WAVE2):** Verifies deep-dive agents completed
- **G4 (Pre-WAVE5):** Blocks output without critic approval

**Benefits:**
- Prevents bypassing mandatory interview stages
- Ensures quality verification before syllabus generation
- Enforces repair loop for rejected content

---

### Telemetry Layer

Every wave transition now logs to `phase_telemetry` table:

**Tracked Metrics:**
- `started_at` - Phase start timestamp
- `completed_at` - Phase completion timestamp
- `duration_seconds` - Total phase duration
- `gate_result` - PASS/FAIL/SKIP
- `success` - 1 = success, 0 = failure
- `error_message` - Error details if failed

**Example Query:**
```sql
SELECT phase, wave, duration_seconds, gate_result, success
FROM phase_telemetry
WHERE goal_id = :goal_id
ORDER BY started_at;
```

### Budget Enforcement

Users can now define agent budget limits during interview:

**Budget Options:**
- `10` - Conservative (limited spawns)
- `20` - Balanced (default)
- `50` - Aggressive (extended research)
- `-1` - Unlimited (no constraints)

**Enforcement Modes:**
- `advisory` (default) - Warnings at thresholds, no blocking
- `hard_limit` - Blocks agent spawns when exhausted

**Implementation:**
```bash
# Before each agent spawn
BUDGET_STATUS=$(sqlite3 ~/.learnloop/goals/{goal_id}/memory.db < docs/learnloop/mcp-queries/gates/budget-check.sql)

IF BUDGET_STATUS = 'EXHAUSTED' AND enforcement = 'hard_limit':
  # Block spawn, force approve
ELSE:
  # Emit warning, proceed
```

### Critic Repair Loop

Enhanced critic agent with **mandatory repair loop**:

**Before v2.0:**
- Critic rejected → manual intervention required
- No retry mechanism

**After v2.0:**
- Automatic repair up to 5 cycles
- Each repair: minimum 10 WebSearch calls
- Force approve after max cycles with warnings

**Flow:**
```
Critic rejects → Repair agents spawn → Update topics → Re-run critic
    ↓
If still REJECT and cycles < 5 → Loop again
    ↓
If cycles >= 5 → Force APPROVED_WITH_WARNINGS
```

## Breaking Changes

### Mandatory Interview
- Goals cannot be created without completing 3-stage interview
- Existing goals without interview data will be blocked at WAVE1

**Migration:** Run interview for existing goals or manually set:
```sql
UPDATE goal_meta SET 
  onboarding_complete = 1,
  goal_interview_complete = 1
WHERE goal_id = :existing_goal;
```

### Budget Column Required
- New goals require `agent_budget` integer (default: -1)
- New goals require `budget_enforcement` text (default: 'warning')

**Migration:** Update existing goals:
```sql
UPDATE goal_meta SET 
  agent_budget = -1,
  budget_enforcement = 'warning'
WHERE agent_budget IS NULL;
```
